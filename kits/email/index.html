How to use

Every template is a self-contained <html> document. Inline styles only, table-based layout, 600px outer width, system font stack. You paste, swap placeholders, and ship.

  1. Open the template file and copy the full HTML.
  2. Paste it into your provider's template editor (Postmark templates, Resend React-email export target, SES template HTML field).
  3. The placeholders use {{snake_case}} — rename to match your provider's syntax if it differs (Postmark uses {{name}}, Mailgun uses %recipient.name%).
  4. Send a test to mail-tester.com and your own Gmail + iOS Mail before going live.

Render with your own colors

The hex values were lifted by hand from tokens.css. Each template has a header comment block pinning the values it uses — open any template and you'll see the token-to-hex map at the top. Change a hex there, then find-replace through the file (every styled element references the hex directly — we deliberately avoided CSS custom properties because Gmail webmail strips them).

Client compatibility notes

The templates target Gmail webmail, iOS Mail, Outlook 365 for web, and Yahoo. The structural rules:

  • Tables for layout. No flexbox, no grid — the gallery page above uses grid, the emails do not.
  • Inline styles on every rendered element. The <style> block holds only the mobile @media collapse and CTA hover states.
  • No CSS custom properties anywhere inside the email body. Hex values are pasted directly so Outlook desktop and Gmail strip-style passes don't degrade them.
  • System font stack only. Atkinson Hyperlegible is not safe to webfont-load in email.
  • Outer table 600px wide; @media (max-width: 620px) collapses the card to 100% width on iOS Mail / Apple Mail. Outlook desktop ignores media queries and gets the 600px fixed width, which is fine.
  • Outlook desktop dark mode is not specifically targeted — the warm-paper light palette renders acceptably under its forced color inversion. See README for the punt.
