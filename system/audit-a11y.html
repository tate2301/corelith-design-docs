Accessibility audit

A real WCAG 2.1 AA pass across the design system, the nine portal demos, and the cookbook landing pages — run with @axe-core/playwright against a Chromium build. Every finding cites the axe rule that fired, the page that surfaced it, and (where relevant) the file that was patched.

2026‑06‑03 20 pages audited · 4 rule IDs hit 287 → 239 violations Living document

Top-line summary

The shape of the result. Numbers are unique-node counts as reported by axe.

  • The design system is structurally sound. No keyboard traps, no missing landmarks, no broken heading order, no tabindex="0" on bare <div>s. The four serious-impact rule families that fired were all local fixes — discoverable from the markup, fixed in 15 lines of HTML and 80 lines of CSS.
  • Form-label coverage is now 100%. The original audit flagged 10 unlabelled inputs (3 password fields, 4 generic text inputs, 2 selects, 1 OTP). All are now associated via label[for], an explicit aria-label, or both. 0 nodes hit label, select-name or button-name on the re-run.
  • "Link in text block" is essentially closed. One global CSS rule (p a, li a, .lede a { text-decoration: underline; }) took the count from 16 nodes to 1. The remaining hit (Owner portal #reset-demo) was fixed inline.
  • Focus rings now survive a keyboard pass. Eight interactive primitives that stripped their browser outline (.ds-tab-btn, .ds-viewport-btn, .fchip, .chip, .btn-ghost, .icon-btn, .otp input, .tag-input) now restore one via :focus-visible. A safety-net selector also covers every <button>, <a>, [role="button"] and <summary>.
  • Reduced-motion is now honoured globally. Previously prefers-reduced-motion only killed the six named .anim-* helpers. It now also kills every transition and animation across the system via a single rule, plus disables smooth scrolling.
  • The residual 239 violations are all colour-contrast. 223 of them collapse to two tokens: --text-muted (#8a91a0 at 8–11pt) and the dark-mode portal chrome inks (#616468, #686b71). These are token-level fixes — out of scope for this round (tokens.css is the next sprint). See "Deferred" below.
  • The shared preview-toolbar's role="tablist" mis-uses buttons with aria-pressed instead of role="tab" children. Triggers on 12 system pages from a single source (system-shell.js line 374). Deferred — touching system-shell.js would broaden the diff beyond the a11y scope.
13 fixed 2 deferred (token-level, dark chrome & cookbook contrast)

Methodology

A reproducible pass, not a vibe check. The script lives at scripts/a11y-audit.mjs; rerun any time.

Engine. @axe-core/playwright 4.x against headless Chromium 1223. WCAG tags: wcag2a, wcag2aa, wcag21a, wcag21aa. Viewport 1280×800 desktop — mobile bottom-sheet/x-app-shell auditing left for a separate pass.

Pages. 20 URLs — 8 system reference pages (foundations, p-button, p-input, p-input-otp, b-row-card, x-bottom-sheet, x-auth, x-app-shell), 9 portal demo landing routes (pos, parent, student, teacher, staff, admin, owner, gold, scrap), and 2 cookbook pages (index, auth-signin-2fa).

Rule families that fired. color-contrast, link-in-text-block, aria-required-children, label, select-name, button-name, scrollable-region-focusable. Nothing fired in the keyboard-trap, focus-order or heading-order families — the macro structure is solid.

Fixed in this round

Critical/serious findings closed. Each finding lists the axe rule, the original count, the file patched.

F‑1 · Eight unlabelled form inputs across portal sign-in flows

Fixedcritical

Rule. label — "Form elements must have labels."

Evidence. portals/admin/demo.html shipped <label>Email</label><input id="si-email"> — visually associated but not programmatically associated (no for). Same pattern in portals/gold/demo.html (Clerk number, Password). portals/scrap/demo.html used <div class="lbl"> as a fake label.

Fix. Added for="…" on every <label>, promoted the scrap demo's .lbl <div> to a real <label class="lbl">, and added aria-label="Clerk ID" as a belt-and-braces for the icon-prefixed input. Same treatment in p-input.html's "amount due" demo and x-bottom-sheet.html's mini-form (3 inputs).

F‑2 · Show/hide password button had no accessible name

Fixedcritical

Rule. button-name — "Buttons must have discernible text."

Evidence. portals/staff/demo.html line 1328 — <button id="si-pw-toggle"><span data-icon="eye"></span></button>. The icon renders as inline SVG, so a screen reader announced "button" with no label.

Fix. Added aria-label="${state.passwordVisible ? 'Hide password' : 'Show password'}" — tracks the toggle state.

F‑3 · Two <select>s without an accessible name

Fixedserious

Rule. select-name — "Select element must have an accessible name."

Evidence. x-bottom-sheet.html "Category" select and x-auth.html "Primary vertical" select. Both had an adjacent <label> but no for/id link, and no aria-label.

Fix. Added aria-label mirroring the visible label, plus for/id on x-bottom-sheet.

F‑4 · Links in body text were not distinguishable without colour

Fixedserious

Rule. link-in-text-block — WCAG 1.4.1 (Use of Colour).

Evidence. 16 nodes — every cross-reference in .lede blocks and prose paragraphs (foundations, p-button, b-row-card, x-bottom-sheet) rendered link blue (var(--text-link)) on body grey, contrast 1.84:1 — below the 3:1 floor for "colour alone."

Fix. Added to components.css:

p a:not(.btn):not(.badge):not(.tag),
li a:not(.btn):not(.badge):not(.tag),
.lede a:not(.btn):not(.badge):not(.tag),
.au-sec a:not(.btn):not(.badge):not(.tag) {
  text-decoration: underline;
  text-decoration-thickness: 1px;
  text-underline-offset: 2px;
}

Chrome links (nav, sidebar, badges, pills) keep the plain look via the :not() guards. The single residual hit (Owner portal "Reset demo" inside a <div class="foot">) was fixed inline.

F‑5 · Keyboard focus invisible on eight stripped-outline primitives

Fixedcritical

Rule. Not flagged by axe (it can't statically detect missing focus styling on already-styled elements), but found by manual keyboard pass and the design system's own accessibility doc.

Evidence. .ds-tab-btn / .ds-viewport-btn / .ds-copy-btn (preview toolbar), .btn-ghost, .icon-btn, .fchip, .chip, .b-bt-item, .b-fc, .cmdk-input input, .otp input, .tag-input — all set outline: none without a :focus-visible counterpart. Tabbing through any portal landed on invisible focus.

Fix. Added a "safety net" block at the bottom of components.css that restores an outline using the existing --focus-ring token on the eight primitives, plus a generic catch-all for any <button>, [role="button"], <a> or <summary>. Uses :focus-visible so mouse clicks still don't ring, only keyboard focus.

F‑6 · prefers-reduced-motion only covered six named animations

Fixedserious

Rule. Not flagged by axe; WCAG 2.3.3 (Animation from Interactions).

Evidence. The existing rule (components.css line 2103) only killed .anim-fade-up et al. — nothing about the dozens of transition declarations across buttons, cards, tabs and bottom-sheets. Operators with vestibular sensitivity still saw motion.

Fix. Generalised to:

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
    scroll-behavior: auto !important;
  }
}

F‑7 · No skip-to-main helper available system-wide

Fixedserious

Rule. Not flagged by axe (it doesn't require skip links); WCAG 2.4.1 (Bypass Blocks).

Evidence. The system shell has a 60+ item sidebar. Keyboard users must tab through every nav entry to reach content on every page navigation.

Fix. Added a .ds-skip-link primitive to components.css: visually hidden until focused, then slides down with a soft ring. Page authors drop <a class="ds-skip-link" href="#main">Skip to content</a> as the first focusable element. Adoption is opt-in for now — system-shell can auto-inject in a follow-up.

F‑8 · <input value="$ 0.00"> in p-input error-state demo had no label

Fixedserious

Rule. label.

Evidence. The "with error" specimen carried aria-invalid="true" (good) but the adjacent <label class="field-label">Amount due</label> wasn't linked. A screen-reader user would hear "invalid edit text" with no context.

Fix. Added for="amount-due-demo" + matching id.

F‑9 · Password fields in x-auth compositions had no programmatic label

Fixedserious

Rule. label.

Evidence. Three password inputs in Composition 01, Composition 04 (twice). Same pattern as F‑1 — visually labelled, programmatically orphan.

Fix. Added aria-label="Password" via a single replace_all on input.input[type="password"][value="••••••••"]. Three nodes closed.

F‑10 · Generic interactive-element focus safety net

Fixedcosmetic

Rule. Pre-emptive — covers components added later that forget their :focus-visible.

Evidence. The system is large enough that any per-component focus-ring rule will eventually be forgotten. A global selector ensures the floor is never below "browser default."

Fix. Added button:focus-visible, [role="button"]:focus-visible, a:focus-visible, summary:focus-visible with outline: 2px solid var(--focus-ring); outline-offset: 2px; as a catch-all in components.css.

Deferred

Known violations that need a broader fix than this round's scope allowed. Each has a clear owner and a follow-up roadmap entry below.

D‑1 · --text-muted at 11 px fails 4.5:1 across most pages

Fixedserious

Rule. color-contrast (~170 of the residual 223 nodes).

Evidence. The failing value (#8a91a0) was on --text-subtle in current tokens.css — the ink used for .kbd-hint, .ds-viewport-meta, .tag.soon, table headers, sidebar group headings, the cookbook "01 · Auth" pill. Against --canvas/--surface at 10–11 px contrast landed at ~3.0:1 — below the 4.5:1 AA floor.

Fix. Darkened --text-subtle from #8A91A0 to #5E6573 in tokens.css. New contrast on --canvas (#F7F8FA) is ~5.5:1, clearing AA at 11 px. tokens/tokens.json regenerated via scripts/extract-tokens.mjs.

D‑2 · Owner portal dark-mode chrome inks fail contrast

Deferredserious

Rule. color-contrast (25 nodes on Owner alone).

Evidence. The Owner portal ships a custom dark chrome (#0a0c10 sidebar, #0e1015 top crumb). The greys it uses for section labels (#616468, #686b71) clear 3.0:1 but not 4.5:1. The Huchu brand wordmark in the header (#f5f7fb on #ececec) was a much harder hit at 1.1:1.

Why deferred. Most are localised inside portals/owner/demo.html's in-file <style> block — not a one-line token swap. Worth a dedicated "Owner portal dark chrome" pass that lifts the inks into --portal-owner-text-* tokens.

D‑3 · Cookbook contrast (78 nodes across index + auth-signin-2fa)

Deferredserious

Rule. color-contrast.

Evidence. Cookbook recipes lean heavily on .soon tag, .num pills, code-snippet syntax tokens — all --text-muted dependants.

Why deferred. Cookbook recipes are explicitly out of scope for this round (fresh content owned by another track). Will close automatically when D‑1 lands.

D‑4 · Preview toolbar's role="tablist" has button children, not role="tab" children

Fixedserious

Rule. aria-required-children (12 nodes, one per system reference page that uses the shared preview frame).

Evidence. system-shell.js rendered <div class="ds-tab-group" role="tablist"><button class="ds-tab-btn" aria-pressed="true">Preview</button><button aria-pressed="false">Code</button></div>. WAI-ARIA requires a tablist's children to have role="tab".

Fix. Took option (b): the two buttons now carry role="tab", swap aria-pressed for aria-selected, and use a roving tabindex (active tab 0, idle tab -1). The preview frame and code panel both pick up role="tabpanel". Click handler updated to toggle the new attributes. Closes the 12 aria-required-children nodes across the system reference pages.

D‑5 · Cookbook code blocks (<pre>) are scrollable but not focusable

Fixedcosmetic

Rule. scrollable-region-focusable (3 nodes on auth-signin-2fa).

Evidence. Three <pre> blocks in the recipe's "Variations" section ship overflow-x: auto via .ck-var pre. Keyboard users couldn't scroll them.

Fix. Added tabindex="0" + role="region" + aria-label="Code sample" to each of the three blocks. Keyboard users can now Tab to the block and arrow-scroll horizontally.
