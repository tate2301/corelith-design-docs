Print stylesheet

A single print.css file that turns any portal page, receipt, invoice, or audit view into a clean, ink-budget-conscious printed page. A4 and US Letter both supported.

Stable print.css A4 + Letter Pure black on white CSS only

The contract

Load print.css after tokens.css and components.css. Everything below kicks in only inside @media print. 

<link rel="stylesheet" href="../tokens.css" />
<link rel="stylesheet" href="../components.css" />
<link rel="stylesheet" href="../print.css" />

Behaviour

  • Strips shadows, gradients, soft surfaces — pure ink only.
  • Forces pure black #000 text on white background.
  • Body sets to 10pt; tables 9pt; footnotes 8pt.
  • @page defaults to A4 with 18mm/16mm margins.
  • US Letter is honoured via the @media print and (max-width: 9in) branch with 0.75in/0.6in margins.
  • Hides navigation: .hx-topbar, .hx-footer, .ds-sidebar, .huchu-side, .ds-toc, .ds-pager, and any element with data-print="hide".
  • Tables use border-collapse: collapse with 1pt black borders and prevent breaking mid-row.
  • Cards (.b-card, .surface-card, .b-callout) keep page-break-inside: avoid.
  • Body links get their URL annotated: a (https://example.com) — except inside [data-print-quiet] zones.

Attribute contract

Three opt-in attributes that any page author can sprinkle on a DOM node to control how it prints.

Attribute Effect on print Use it for
data-print="hide" display: none !important; Toolbars, "Print" buttons, in-app banners.
data-print="block" display: block !important; Force-show a page header or stamp that's hidden on screen.
data-print-quiet Suppresses the (url) annotation after links inside the element. Header crumbs, in-text app links, breadcrumb trails.

Tokens that are collapsed

The print media block flattens the design-system palette so every token resolves to pure ink:

  • --canvas, --surface, --surface-muted, --brand-soft → #fff
  • --text, --text-strong, --text-body, --brand → #000
  • --text-muted → #333; --text-subtle → #555
  • --border → #000; --border-subtle → #888
  • All --shadow-* → none

Tips for authors

Three things that make a page print well on the first try.

Tip. Open Chrome DevTools → Rendering tab → Emulate CSS media → print to see what the printer will see, without having to hit Print every time you tweak a rule.
  1. Wrap the document in a container. The samples use <article class="print-paper">. On screen that gives you a paper-like card; in print it collapses to the full page.
  2. Mark chrome with data-print="hide". Anything the printer shouldn't see — Print buttons, in-page toolbars, intro paragraphs — gets this attribute.
  3. Right-align money. Use class="num" on <td> and <th> for any numeric column — it switches to tabular mono and right-aligns.
  4. Test both papers. Print preview → switch between A4 and Letter and make sure the totals block, signature, and footer still fit on the page.

Page-break helpers

  • tr { page-break-inside: avoid; } — rows stay whole.
  • thead { display: table-header-group; } — header repeats on every page of a long table.
  • .b-card, .surface-card { page-break-inside: avoid; } — small cards don't split.
  • h2 { page-break-after: avoid; } — headings don't orphan from their first paragraph.

What we punted

  • Custom paper sizes beyond A4 and US Letter (no Legal, A5, B5, or thermal-specific @page rules — the receipt sample provides an opt-in @page receipt hint only).
  • Running headers/footers via position: running() (Paged Media Level 3) — currently only Prince/AntennaHouse render it. The audit sample fakes the page header with a plain block instead.
  • Watermarks, barcode rendering, and digital-signature glyphs — provided by downstream renderers, not the stylesheet.
