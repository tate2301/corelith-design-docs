What’s blocking dev adoption P0

The bar isn’t "the docs are nice." The bar is "a dev with no Huchu context can ship a feature from the cookbook without DM’ing anyone." These items are what stand between us and that bar.

P0·01 Ship the @tate2301/corelith package Every recipe imports from @tate2301/corelith. That package doesn’t exist as a published artifact yet — it lives in tate2301/huchu. Cut a first version (even an alpha tag) so the snippets are real.
P0·02 Resolve the audit’s critical-three Overlay overlap (modal / modal-window / bottom-sheet), the four portal tab aliases still in flight, and the duplicated data-toolbar variants. Until these collapse, "use the system" means "pick the right one of three." See audit.
P0·03 Recipe coverage gap 13 recipes cover the cookbook themes but not the long tail of "how do I…" questions devs actually ask. Target gaps: bulk edit, role-gated views, offline-first writes, import wizard, notifications inbox.

Important polish P1

None of these block a hand-rolled adoption. All of them widen the on-ramp.

P1·01 Runnable snippets Every data-code block in a recipe should mount in a sandbox the reader can poke. CodeSandbox embed or in-page iframe — either works.
P1·02 Demo ↔ recipe cross-links Each portal demo links to the cookbook recipe(s) that compose it. Each recipe links to the portal that ships it. Bidirectional, not just downstream.
P1·03 Accessibility pass A11y checklist exists. Make it a CI gate — axe-core on every recipe + portal demo, flag missing labels and contrast.
P1·04 Visual regression Shipped Playwright snapshots of every system page. Bot posts diffs on PRs. Catches the silent "components.css change rebroke the date picker" failures. Shipped: .github/workflows/visual-regression.yml runs scripts/visual-diff.mjs against a curated set of cookbook + portal + system surfaces at mobile and desktop. Baselines live in /visual-baselines/; refresh with node scripts/visual-baseline.mjs.
P1·05 Dark tokens Two portals already ship a dark variant ad-hoc. Promote into tokens.css as a media-query block so every page benefits.
P1·06 Mobile sweep Every reference page should be readable on a phone. Today the sidebar collapses but a few specimen blocks scroll horizontally.
P1·07 Plain-language pass Voice rules exist; not every page obeys them. One editing pass per quarter against voice + content guidelines.

Tooling & governance P2

The boring scaffolding that makes the system survive a contributor turnover.

P2·01 Install story Shipped Today: install.html describes the static + Next.js paths. Bring it up to the moment @tate2301/corelith ships. Shipped: install.html and get-started.html now honestly split CSS-today vs. React-pre-alpha paths and link the published-package ETA to the React package changelog.
P2·02 Search Pagefind scaffold is wired (/search.html). Add the build step that runs npx pagefind --site . at deploy.
P2·03 CI JS parse check is hard-failing on every PR. HTML structure and broken-link checks are soft-failing until html-validate and lychee are pinned to the runner.
P2·04 Versioning Cut a semver tag every time tokens or components.css changes. Update the changelog on the same PR.
P2·05 Custom domain Move from the Vercel preview URL to design.corelith.<tld>. One DNS record, one Vercel config change.
P2·06 Contributor guide See CONTRIBUTING.md. Filename conventions, PR shape, RFC process. Land it on day one, refine as habits emerge.
P2·07 Live sandbox A CodeSandbox / StackBlitz template that imports the latest @tate2301/corelith and renders an empty page header. Link from every recipe.
P2·08 Token export Tokens.css is the source. Also export JSON, Figma Tokens Studio, and Tailwind v4 @theme blocks from a single build step.

Long-tail P3

Want-to-haves. None of these gate adoption; all of them widen who the system serves.

P3·01 i18n Shipped (scaffold) Strings in primitives are English-only. Promote labels to a key/value table so locale packs are a future add. Shipped scaffold: i18n reference, starter resource packs (en, sn, nd) with ~30 keys covering auth/errors/actions/units/datetime, and a full recipe at cookbook/i18n-localized-app. Primitives still need the useT() wiring — the scaffold is the floor, not the ceiling.
P3·02 RTL Layout uses logical properties in most places. Audit the rest. One test page with dir="rtl" covers most of the surface.
P3·03 Print A real @media print stylesheet for invoices, receipts, and audit views.
P3·04 Email kit Token-mapped email templates (table-based, inlined). Owner notifications, approval requests, sign-in codes.
P3·05 Marketing surface A small marketing-page kit that re-uses tokens but bends rhythm and density for landing-page use.

Suggested rollout

Six two-week sprints. Order is deliberate: package first, audit fixes second, governance last. Each sprint names a primary owner so nothing falls through.

Sprint 1 Package & ship Cut @tate2301/corelith alpha. Wire the cookbook’s data-code blocks against it. Owner: DS lead.
Sprint 2 Audit critical-three Collapse overlay overlap; finish the portal tab alias migration; one canonical data-toolbar. Owner: components owner.
Sprint 3 Recipe gap Add the five missing recipes (bulk edit, role gate, offline writes, import wizard, notifications). Owner: docs lead.
Sprint 4 Polish pass Runnable snippets, demo↔recipe cross-links, a11y CI gate, dark tokens, mobile sweep. Owner: rotation.
Sprint 5 Search & versioning Pagefind in the build, semver tag rhythm, changelog discipline, custom domain. Owner: infra.
Sprint 6 Governance Contributor guide live, RFC process in use for one real new pattern, sandbox template linked from every recipe. Owner: DS lead + infra.
