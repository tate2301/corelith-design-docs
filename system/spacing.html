Four-pixel base, eight-pixel rhythm. The product is dense by nature; the chrome around it isn't. Generous air over hairline borders.

Density modes

The system ships one density. There is no .is-dense or --density modifier in components.css — the default 36 px control height was tuned to be the dense desktop default already, and mobile portals lift to 44 px through component variants (.btn-lg, etc.), not a density flag.

SurfaceEffective densityHow it's achieved
Desktop ERP shellDense (36 px controls, 8 × 12 cell padding)System default
Mobile portal (POS, parent, student)Touch (44 px controls, 12 × 16 cell padding)Component variants — .btn-lg, .input-lg
Data table in a settings pageComfortable (40 px row, 12 × 16 cell)Component variant — .p-table.comfortable

Adding a global density token has been considered and rejected: most density problems are solved at the component level (a denser table, a smaller chip), and a global flag would force every surface to re-test every state.

Eight-point rhythm

The base unit is 8. Doubled at 16 for component padding; doubled again at 32 for section gaps. Half-step (4) only for tight contexts — toolbar chips, table cell content.

Control heights

Four control sizes. 36 px is default — the touch-friendly compromise between desktop density and finger-friendliness. Mobile portals lift to 44 px.

Do & don't

Do

Use a token. padding: var(--space-4) is always 16 px and stays in rhythm.

Don't

Type 15px anywhere. Round to the nearest token — usually --space-4 (16 px).

Do

Use bigger gaps between sections (48 px) than within them (16 px). Hierarchy is communicated by space.

Don't

Cram primary actions into 28 px tall controls. Anything that gets clicked is at least 36 px.
