JSON export pipeline

Tokens live in tokens.css as the source of truth. A small Node script projects them into the design-tokens JSON format used by Style Dictionary, Figma plugins, and downstream platforms.

FilePurpose
tokens.cssSource of truth · CSS custom properties consumed by every page.
scripts/extract-tokens.mjsParses tokens.css, splits the :root and body.is-dark blocks, and emits both JSON files.
tokens/tokens.jsonLight / default cascade — design-tokens shape ({ value, type, description? }).
tokens/tokens.dark.jsonDark cascade overrides only — same shape, applied on top of the light file.
tokens/style-dictionary.config.jsonStyle Dictionary configuration — drives the platform-specific builds (Swift, Android, JS).

Workflow

# 1. Edit tokens.css (the source of truth)
$ vim tokens.css

# 2. Regenerate the JSON projections
$ node scripts/extract-tokens.mjs
  → wrote tokens/tokens.json
  → wrote tokens/tokens.dark.json

# 3. Optional — feed into Style Dictionary for native platforms
$ npx style-dictionary build --config tokens/style-dictionary.config.json

The script is intentionally dependency-free — it only reads tokens.css with a regex parser. Adding a new token means adding it to tokens.css and re-running the script; downstream consumers pick it up automatically.

Use elsewhere

A second exporter (scripts/export-tokens.mjs, run via npm run tokens) ships the same tokens in three downstream-ready shapes.

  • tokens/corelith.json — for Figma (Tokens Studio plugin / W3C Design Tokens shape).
  • tokens/corelith.tailwind.css — for Tailwind v4: @import once and the @theme block is wired up.
  • tokens/corelith.flat.json — for raw JS / native pipelines: flat name → value map with a _dark overlay.

See tokens/README.md for the radius-scale mapping and dark-theme conventions.
