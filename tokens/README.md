# Huchu Design Tokens — JSON Exports

Machine-readable exports of every token defined in [`../tokens.css`](../tokens.css).
The shape follows the [Design Tokens Community Group draft format](https://design-tokens.github.io/community-group/format/) and is directly consumable by [Style Dictionary](https://amzn.github.io/style-dictionary/).

## Files

| File                          | What it contains                                                                |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `tokens.json`                 | Every token under `:root` in `tokens.css` — the default (light) cascade.        |
| `tokens.dark.json`            | The `body.is-dark` overrides only. Merge over `tokens.json` for the dark theme. |
| `style-dictionary.config.json`| A starter config for downstream consumers who use Style Dictionary directly.    |

Both JSON files are generated by [`../scripts/extract-tokens.mjs`](../scripts/extract-tokens.mjs).
**Do not edit them by hand.** Update `tokens.css` and re-run:

```bash
node scripts/extract-tokens.mjs
```

## Consuming the tokens

### Figma — Tokens Studio plugin

1. Open [Tokens Studio for Figma](https://tokens.studio/).
2. **Settings → Sync providers → JSON / Git** — point at this folder.
3. Push the `tokens.json` file. Use a separate set/theme for `tokens.dark.json` and mark it as an overlay over the default set.

### Tailwind config (JS)

```js
// tailwind.config.mjs
import tokens from "../tokens/tokens.json" with { type: "json" };

const c = tokens.color;

export default {
  theme: {
    extend: {
      colors: {
        brand: c.brand.base.value,
        "brand-strong": c.brand.strong.value,
        "brand-soft": c.brand.soft.value,
        canvas: c.canvas.value,
        surface: c.surface.base.value,
        ink: c.ink.base.value,
      },
      borderRadius: Object.fromEntries(
        Object.entries(tokens.radius).map(([k, v]) => [k, v.value])
      ),
      spacing: Object.fromEntries(
        Object.entries(tokens.space)
          .filter(([, v]) => "value" in v)
          .map(([k, v]) => [k, v.value])
      ),
    },
  },
};
```

### iOS (Swift)

Run Style Dictionary against `style-dictionary.config.json` to emit
`dist/ios/Tokens.swift` — a `HuchuTokens` class with typed constants:

```bash
npx style-dictionary build --config tokens/style-dictionary.config.json
```

```swift
import UIKit

view.backgroundColor = HuchuTokens.colorCanvas
label.textColor      = HuchuTokens.colorTextStrong
button.layer.cornerRadius = HuchuTokens.radiusMd
```

### Android (XML)

The same SD invocation emits `dist/android/tokens.xml`:

```xml
<color name="color_brand_base">#FF0B5DF0</color>
<dimen name="radius_md">8dp</dimen>
```

Reference from layouts: `@color/color_brand_base`, `@dimen/radius_md`.

### Web (raw JSON, no SD)

```js
import tokens from "./tokens/tokens.json" with { type: "json" };

document.documentElement.style.setProperty(
  "--brand",
  tokens.color.brand.base.value
);
```

## Token shape

```jsonc
{
  "color": {
    "brand": {
      "base":   { "value": "#0B5DF0", "type": "color", "original": "--brand" },
      "strong": { "value": "#0944C2", "type": "color", "original": "--brand-strong" },
      "soft":   { "value": "#E8EFFE", "type": "color", "original": "--brand-soft" }
    },
    "tone": {
      "success":    { "value": "#5E8E54", "type": "color" },
      "success-bg": { "value": "#E7EFE0", "type": "color" }
    }
  },
  "space":  { "4": { "value": "16px", "type": "spacing" } },
  "radius": { "md": { "value": "8px", "type": "borderRadius" } },
  "shadow": { "rest": { "value": "0 1px 0 rgba(42,38,34,0.04)", "type": "boxShadow" } },
  "font":   { "sans": { "value": "\"Atkinson Hyperlegible Next\", …", "type": "fontFamilies" } }
}
```

`{path.to.token}` strings inside `value` are Style-Dictionary aliases pointing
at another token, equivalent to `var(--…)` in CSS.

## Versioning

The tokens are versioned with the design system as a whole — see
[`../VERSION`](../VERSION) and [`../system/changelog.html`](../system/changelog.html).
Breaking changes (renames, removals) bump the **minor** version pre-1.0 and
the **major** version after 1.0.
